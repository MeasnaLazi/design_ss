# apps_publisher — Cleanup Plan

*Analysis only. No code changed. Revised 2026-07-12 (v3).*

## Current workflow (confirmed with you)

1. **Composer** designs the strip as **HTML** (`composer/render.mjs` → PNGs, reviewed against references).
2. When it looks good, **`composer/import-to-canvas.mjs`** replays the strip **into the live Canvas** as editable layers.
3. A human hand-finishes in the **`web_ui` Canvas editor**.

What's retired is the *old live agent op-by-op authoring loop* — **not** the canvas, not the import, not the bridge that import rides on.

## ⚠️ Correction to earlier versions

v1–v2 proposed removing the "agent bridge." **That is now cancelled.** `import-to-canvas.mjs` drives the canvas through exactly that bridge (`/__api/screenshot-designer/` `mode`, `enqueue-command`, `command-events` SSE, `session`, `agent-preview-data`). Removing it would break your import step. The bridge is **KEEP**.
